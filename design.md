# LifeOS — definitive native visual design specification

## 1. Authority, references, and product grammar
- Status: implementation contract, 2026-09-08. This document specifies the target; it does not certify the current app or any device/provider runtime.
- Scope: native SwiftUI iPhone/macOS and WidgetKit. This authoring task changes only root `design.md`; no code, tests, coordination edits, or commits are authorized by it.
- Precedence: explicit user requirements → this visual contract and `tasks/design-overhaul-plan.md` → current data/domain contracts. Supersede older Iconoir/custom-font/amber-estimate guidance; retain data authority, consent, privacy, and durable receipt rules.
- Read with repo `AGENTS.md`, `Coordination/HANDOFF.md`, and `Coordination/DECISIONS.md`. Owners below are paths relative to this repo; named replacement contracts are requirements, not claims that those APIs already exist.
- Palette authority: `/Users/georgdomke/Library/Mobile Documents/com~apple~CloudDocs/geon/colors.md`; preserve its complete blue ramp, especially main blue `#0253C4`.
- [Skills UI Clean](https://www.skillsui.app/skills/clean): use whitespace to express hierarchy, one primary action, consistent primitives, limited neutral surfaces, explicit accent, complete hover feedback, and useful empty-state content. These are inspiration principles; all measurements below are LifeOS decisions.
- [Forever Components Infinite](https://forevercomponents.com/infinite/): use the supplied brief's structured animated-component-registry approach, cheap mobile-ready patterns, palette/type adaptation, reduced motion, and minimal dependencies. The site could not be retrieved during this review; no individual component or animation was verified or copied.
- Implement these influences using SwiftUI, Core Animation, Swift Charts, and narrow UIKit/AppKit bridges only. No HTML, CSS, web view, copied markup, npm animation package, or runtime web dependency enters the app.
- Screenshot baseline is the user's reported failure set: oversized Finance unavailable panels, inconsistent navigation icons, repetitive/unreachable Calendar, missing focal Mac pinch, sparse Recovery, clipped Biology, and badly proportioned meal review. Image attachments were not present in this authoring context; QA must retain the actual before captures, not invent a visual comparison.
- North star: page identity → meaningful status/value → next action → supporting evidence. Spend visual space in proportion to information, not to the number of backend capabilities.
- Do: align edges; group related decisions; label provenance; use real zero; reveal detail on intent; keep controls predictable; make sparse content compact and useful.
- Don't: stack cards inside cards; repeat the same unavailable sentence; fill missing data with decorative graphs; color every module; animate numeric truth through invented intermediate values; hide a working escape from an empty filter.
- No Advisor, generic AI chat, coaching generator, or advice entry point. Usage remains factual provider consumption; meal-photo calorie estimation remains the sole in-app AI workflow.

## 2. Typography: one SF Pro facade
- Owner: `ios/Shared/Typography.swift`, with geometry tokens in `ios/Shared/DesignTokens.swift`. Use `.system(size: scaledSize, weight: roleWeight, design: .default)`; Apple chooses SF Pro optical rendering. No named SF font file, rounded face, or custom font registration.
- Exact sizes below are points at iOS Large/default content size; use the same base sizes on Mac. Implement each custom size with `@ScaledMetric(relativeTo: anchor)` feeding `.system(size:)`; `.system(size:)` alone does not establish Dynamic Type scaling. Do not scale an already semantic font twice.
| Role / facade | Base size / anchor | Weight / tracking | Use |
| --- | --- | --- | --- |
| pageTitle | 28 / `.title` | bold / −0.4 pt | One visible page identity; never duplicate with a large navigation title |
| sectionTitle | 20 / `.title2` | semibold / −0.2 pt | Major section, 24 pt separation above |
| cardTitle | 17 / `.headline` | semibold / 0 | Related metric or chart title |
| body | 17 / `.body` | regular / 0 | Explanation, editable input, essential state copy |
| label | 15 / `.subheadline` | medium / 0 | Form label, legend, navigation text |
| metadata | 13 / `.footnote` | regular / 0 | Source, unit, date, freshness; never hide critical reason here |
| metric | 36 / `.largeTitle` | semibold / −0.6 pt | One page/card hero, monospaced digits |
| metricCompact | 24 / `.title2` | semibold / −0.3 pt | Supporting metric; no second competing hero |
| button | 15 / `.headline` | semibold / 0 | Button/selector text; state never changes its width |
- Tracking values stay fixed in points; use tracking 0 at accessibility sizes. Use natural system line metrics; body/state paragraphs add 3 pt line spacing, labels/metrics add none. No uppercase headers except short provenance labels such as `DEMO · NOT LIVE`.
- Use `.monospacedDigit()` for money, dates in changing controls, durations, percentages, and editable numeric values; ordinary names/copy remain proportional. Never use monospaced text as a substitute for tabular digits.
- Value and unit share first baseline with 4 pt gap; unit uses metadata. Keep currency sign and amount together with locale formatting; move a long unit to a second line before shrinking. App metrics never use minimumScaleFactor to defeat text size preferences.
- Preserve currency minor-unit precision; percentages use at most one decimal when the source supports it; source-defined health precision remains source-defined. Unavailable = em dash plus reason; observed zero = formatted 0 with unit. Do not round unknown into zero.
- App supports all Dynamic Type sizes without a global cap: at accessibility1 and above, use one-column cards, vertical metric/unit layouts, wrapping selectors or a labeled menu, and stacked form fields. Essential labels, validation, and state copy have unrestricted vertical growth.
- Nonessential account/event names may use two lines then truncate; full text remains in detail and accessibility labels. Do not truncate values, consent text, save failures, dates that distinguish repeated times, or action names.
- Widgets use fixed family geometry and constrained roles: hero 28, compact metric 22, title 15 semibold, body 13 medium, metadata 12 medium; scale with the above anchors only through `.xxxLarge`, then prioritize content removal, not more shrinkage.
- Widget numeric fallback is 28 → 24 → 22 pt using `ViewThatFits`; never below 22 for the primary value. Calendar grid dates alone may use 11 pt medium. Accessories use system-appropriate 13 pt text/20 pt metric; accessible labels contain unabridged values and state.
- Migration: expand `LifeOSTypography` deliberately; migrate callers and remove obsolete font wrappers, Inter/Space Grotesk/Manrope assets and registrations. Do not retain unused weight-overload APIs or legacy font aliases after the last call site moves.

- Semantic precedence: privacy/availability determines whether a value exists; explicit error/warning labels explain trust; estimate styling overrides the estimated numeric mark's metric color; observed metric color overrides module identity. An estimated calorie value is green and labeled Estimated; its `Calories · kcal` label remains orange.
- Goal/reference line = secondary neutral, 1 pt dashed 2/4; observed = 2 pt solid; estimate = 2 pt dashed 6/4; history = 1.5 pt secondary neutral with `History` label. Do not use green for both estimate and goal on the same graph.
- Chart fills are the matching semantic color at 10% fading to 0%, never the sole encoding. Add line pattern, direct label, or symbol for every semantic distinction. Status-green may appear beside a checkmark but cannot relabel estimates as healthy outcomes.
- Calendar events use one shared observed-blue accent with selected-navigation fill/text pairs; red is reserved for today's/now marker. Navigation icons remain neutral/selected blue, not a multicolor module palette.
- All text pairs must meet 4.5:1 and essential graphics/focus 3:1 in composited captures. Decorative separators need not meet 3:1. If a role fails, fix its token/pair globally; do not hide it with opacity or shadow.
- Grey-wallpaper full-color transparent widgets: clear outer container, inner readable-content backing `#000000` at 60% opacity, radius 12, padding 8; text `#FFFFFF`, supporting text `#E6E6E6`, no additional text opacity. The backing stays behind all essential content, not just the hero.
- That backing is the approved contrast-managed transparency, not a new card/clear user setting. On solid greys `#606060`, `#808080`, `#A0A0A0`, and even white, it provides a dark field; never assume white text alone is readable on grey.
- System-accented/vibrant/clear rendering may remap or remove custom backgrounds: keep text in the system primary group, accent only the key marker, and use shape/weight/state words instead of relying on hue. Never accent both a foreground and its backing into the same tint.
- Use native WidgetKit container/rendering environments with availability guards. If the system cannot preserve the backing in a mode, its native contrast treatment must pass real-device captures; a white-foreground SwiftUI preview is not acceptance. Full-color keeps green/orange; monochrome modes retain `Est.`, `kcal`, dash patterns, and state labels.

## 5. Shared state model and shell/sidebar
- Every module resolves: live (valid current observation), zero (valid observed zero), empty (no observations in scope), stale (retained observation beyond domain freshness), partial (known subset), error (failed operation), plus loading and redacted. Zero is data, not a source state.
- Freshness and coverage come from existing domain timestamps/windows; views do not invent freshness thresholds. Never collapse HealthKit read-indeterminate into permission-denied, or unsupported Zepp behavior into an actionable permission request.
- Error with retained data = retained values plus error notice; error without data = compact recovery state. Partial displays coverage/source qualification beside totals. Redaction immediately removes protected values, tooltips, cached accessibility strings, and widget titles.
- Owners: `ios/LifeOS/Modules/ModuleNavigation.swift`, `ios/Shared/LifeOSIcon.swift`, `ios/LifeOS/LifeOSApp.swift`, `ios/LifeOSMac/LifeOSMacApp.swift`; shared row/frame own appearance. Preserve release-visible route arrays, not every compatibility enum case.
- Layout: Mac sidebar width 224 (resizable 200–260), header 56, primary destinations Home → Calendar → Finance → Fitness → Tax, Settings at bottom; content frame begins after divider. Collapse sidebar below 900 pt window width; restore user width on expansion.
- iPhone tabs remain Home, Calendar, Finance, Fitness, More; More contains Tax and Settings. Usage opens from Home's factual usage summary. Do not promote unfinished compatibility routes into navigation or create an Advisor replacement.
- SF Symbol map: Home `house`, Calendar `calendar`, Finance `creditcard`, Fitness `heart`, Tax `doc.text`, Settings `gearshape`, More `ellipsis`, Usage `chart.bar`; Bank Connections `link`, Investments `chart.line.uptrend.xyaxis`, Documents `folder`, Business `briefcase`, Tasks `checklist`, Grocery `basket`, Shopping `bag`, Reports `chart.bar.doc` for supported internal destinations only.
- Selected rows use the exact selected pair and leading rail; unselected rows use secondary text. Hover uses raised fill without lift; selection preserves symbol outline/weight. Avoid filled-vs-outline swaps, emoji, custom icon assets, and multi-hue badges in shell navigation.
- State map: shell remains stable in live/zero/empty/stale/partial/error; module-level state lives in content, not six duplicated sidebar alerts. An invalid deep link opens a compact destination-unavailable state with Back/Home; navigation itself does not pretend to load.
- Priority: current module action is the page primary; sidebar has no competing CTA. Home no-data layout is a single setup status plus compact module rows; unavailable compatibility routes get one cause/action row, not dashboard skeletons.
- Each module owns route stack, selected date/filter, and semantic scroll anchor. Switching modules restores these; deep link changes only its addressed scope. Back restores originating card focus and position; sheet dismissal restores invoking control; don't force focus during background refresh.
- Mac Tab follows visual order; Return/Space activate, Escape dismisses transient inspection before backing out. On navigation VoiceOver focuses the unique page heading; do not announce the whole sidebar again. Preserve native iPhone interactive-back ownership at the screen's leading edge.

## 7. Calendar: viewport, gestures, and time
- Owners: `ios/LifeOS/CalendarView.swift` owns chrome/date/view/scale state; `ios/Shared/CalendarViews.swift` owns `CalendarTimelineView`, day columns, event/all-day/now rendering and platform bridges; `CalendarLayout.swift` owns pure geometry, arbitration, focal mapping, and DST rules. - iPhone layout: compact month/date toolbar → one day-header row (today/tomorrow/day-after-tomorrow) → all-day strip → one finite vertical timeline viewport → safe-area bottom actions/tab bar. Keep three settled day columns; each horizontal settle advances exactly one day, never replaces the design with a single-day page.
- One 40 pt time gutter sits inside the vertical scroller beside the shared day surface; one hour label per row, one grid line across the three columns. Timeline is edge-to-edge within 8 pt outer inset; header and all-day columns use the same day-width equation `(viewportWidth−16−40)/3`.
- Scroll architecture: `GeometryReader` measures available viewport outside `ScrollView(.vertical)`; one content stack has explicit `24 × hourHeight` grid height. No vertical ScrollView per day, no enclosing page vertical ScrollView, no infinite-height frame, no full-screen high-priority drag consuming vertical pan.
- Pin header/all-day outside timed scroll; all-day shows at most two 24 pt rows plus a 32 pt `+N more` row, with 44 pt combined touch targets. Expansion opens a scrolling all-day sheet, so timed viewport stays usable; `+` supports all-day creation as well as timed creation.
- Default scale 54 pt/hour; minimum 38, maximum 110, shared across timeline views per device. Hour labels use 13 pt metadata; at AX sizes keep three-day geometry and provide an explicit Agenda reading mode with full-sized event text and accessible editing.
- Late-day contract: actual viewport excludes bottom controls via safe-area inset; remaining occlusion O is measured, not hardcoded. Content height H = 24×scale + O + 24 pt endpoint clearance; max offset = max(0,H−viewportHeight). At bottom, 23:45–24:00 is visible above controls with ≤24 pt spare tail.
- Supersede current viewport-sized trailing spacer: reaching late-day content does not require scrolling 24:00 to the viewport top. Do not add an entire blank viewport or double-count home indicator/tab bar. Assert bottom visibility and no oversized tail at 38/54/110 pt/hour.
- Initial today view scrolls once to now−120 minutes, clamped; a non-today first visit starts at 08:00. Preserve wall-time scroll anchor on paging, return, resize, and header expansion. Today button returns date to today and explicitly scrolls to now; refresh never recenters the user.
- Mac keeps existing five-view calendar navigation and inspector. Timed grid owns vertical scroll; horizontal day navigation/overflow is independent. Inspector is 280 pt at window width ≥1180, otherwise presents as a sheet. Header aligns to content columns and time gutter, with no duplicate day titles.
- Mac magnification: capture scale h0, content offset s0, and pointer y p inside timed viewport at gesture begin; focal wall minute m = 60×(s0+p)/h0. Each magnification sample sets h = clamp(h0×factor,38,110), s = clamp(m×h/60−p,0,H(h)−V). Preserve focal time within 1 minute unless edge-clamped.
- Use `MagnifyGesture`/native magnification with an actual start location; use a narrow AppKit event bridge where SwiftUI cannot report the pointer anchor or scroll offset. Never use center-anchored `scaleEffect` on the calendar. Pointer position is frozen at begin; scroll momentum stops before zoom owns the viewport.
- Mac fallback is labeled density − / percentage / +, step 8 pt/hour (clamp endpoints), Reset =54; keyboard-accessible. Buttons animate 160 ms ease-out around viewport center; direct pinch samples never animate. Persist final scale on successful end; cancel restores start scale/offset.

| --- | --- | --- |

## 11. Motion and interruption contracts
- Owner: `ios/Shared/LifeOSMotionKit.swift` with token durations in `DesignTokens.swift`; reuse `LifeOSMotionLifecycle` settlement identity and chart presentation ownership. Timings below are targets; spring response is the response parameter, not a claim of exact wall-clock completion.
| Change | Normal contract | Reduce Motion |
| --- | --- | --- |
| Hover / focus | 120 ms ease-out fill/border; focus ring appears immediately; no lift | Immediate visual state |
| Press / release | 80 ms ease-out to scale 0.98 on standalone button; release 140 ms ease-out; rows use fill only | Fill state immediately, no scale |
| Selector highlight | Spring response 0.24 s, damping 0.90, blend 0; labels stationary | Instant selected fill |
| Page/card-to-detail | Native push/pop; custom same-entity morph response 0.32 s, damping 0.92; one matched geometry owner | Instant layout, optional 100 ms opacity crossfade |
| Chart first reveal | 360 ms ease-out left-to-right clipping mask over final geometry; labels show final truth from start | Final marks immediately |
| Ring first reveal | 420 ms ease-out sweep to bounded final fraction, final numeric label immediately | Final arc immediately |

| Sheet entry/exit | Platform-native interactive transition; custom internal content 180 ms ease-out opacity, no stacked slide | Respect native preference; internal content immediate |
| Refresh / data correction | Existing content stable; replace values/paths without interpolation or reveal; status fade 100 ms | Immediate replacement |

- Chart/ring reveal occurs once per mounted route presentation owner, not on every body update, tab return, range switch, or refresh.
