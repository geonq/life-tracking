# Final NO-GUESSING dispatch checklist
READY FOR LUNA means contracts sufficient for implementation, not source complete, tested or security accepted.
Current phase remains documentation-only. Wait for explicit execution go before editing any source.

## Before a worker receives a packet
- Pin input source SHA and changed-file set; preserve current untracked D1 graph candidates.
- Read R4-READINESS, owning R2-Pxx, R4-16 exact file additions, matching R4-LEAVES/new-features rows.
- Read domain tag/DTO sheets recursively; all types, keys, null rules, limits and conversions are named.
- Use only R4 protocol definitions when R2/R3 disagree; never generate old dictionary SyncFrontier or undefined SyncPage.
- Select matching existing store actor/locked transaction, not parallel DB/model authority; constructors/codecs are fixed.
- Match private helper to existing file/isolation; R4 specifies public boundary and persistent order, mechanical local names may vary.
- Leave raw tax/photos/HealthKit anchors/vault bookmarks/provider secrets out of payloads/archives exactly as whitelist states.
- Preserve existing provider IDs, widget kind/config IDs, source IDs and pending idempotency request bytes.
- Use current pinned dependencies/tool SHA/target membership; no new package or global strict-concurrency suppression.

## Implementation invariants (review checks, not another architecture selection)
- Nullable key present with null; unknown/duplicate keys rejected before mutation; bounds before allocation.
- Decode invokes invariant validators, fieldwise converters preserve IDs/date bits/quantities; no silent sanitize/default of wire.
- Original mutation/disk receipt and outbox committed together; signature later uses frozen bytes; no timestamp conflict winner.
- Applied ACK only after durable projection or full conflict, Planning publication recovery terminal; relay stored ACK only.
- Disk-full, cancellation, replay, out-of-order gap, stale base and revoked epoch behavior match R3/R4 contracts.
- All screen mutations delegate named store/coordinator; animations and widget reload never commit data.
- Array/index work bounded; no repeated full graph/series rebuild per frame; no uncapped network/file body.
- Current OS baseline path compiles independent SDK27; unsupported device capability returns defined result, not fake data.
- Story includes empty/loading/stale/offline/error/denied/cancel/duplicate/concurrent states with exactly one actionable status.
- Typography/spacing/colors/motion/corners use20/27; labels remain readable on grey dark/tinted widgets.
- No generic advisor/coaching AI; only calorie-photo provider flow. No React/JS runtime imported for native motion.

## Revision5 mandatory checks
- Use R5-01 leaf overrides; never attach a finance refresh to a travel trip write, a HealthKit refresh to lifestyle input,
  or a build/storage helper to nutrition retention.
- Persist incoming operations before applying them; enumerate durable ACKs and advance frontiers only after terminal receipts.
- Use DeleteIntent/TombstonePayload and a base-head CAS; empty deletion payloads and timestamp winners are invalid.
- Calendar begin must carry original interval, base head and resize edge; end produces only a changed CalendarCommitIntent.
- Apply the 10,000 ACK bound in all codecs; use R5-04 archive receipts/mappings and purpose-specific historical keys.
- Implement bank readback as the throwing R5-05 contract and preserve cancellation through FinanceCoordinator.

## At wave boundaries
- One Luna implementer at a time; Astra Medium reviews actual diff plus bounded relevant evidence, not an enormous reread.
- Reviewer checks correctness, authority, durability, security, Sendable, complexity, visual hierarchy, cancellation and OS guards.
- Future test/build work belongs execution phase: meaningful batch boundaries/final integrated suite, not every tiny edit.
- Device/server unavailable produces explicit evidence pending, never fabricated PASS or subjective completion percentage.
- If evidence exposes a new architectural contradiction, worker reports exact symbol/input/outcome; controller amends precise contract.
- Missing implementation of an already sealed function is work to do, not a new design question or excuse to replace architecture.
- No claiming Astra acceptance without callable reviewer/provenance; no release green light with missing high-risk evidence.

## Revision6 mandatory checks
- Treat Usage as local-only and Clipper as read-only; do not add them to `SyncDomain`, `SyncStoreKind`, archives or deletion.
- Use R6-02 travel/data registry and receipt schemas; every file/path is registry-owned and every retry is resumable.
- Use JSON embedded ledgers or Planning's existing schema-v3 `journal.sqlite`; never create a second sync database/table family.
- Sign recovery bytes with `LifeOS/recovery-archive/v2`; resolve each operation through its immutable source epoch/key record.
- Write the import receipt before projection and resume by completed store index; success requires durable frontier/widget state.
- Use the one R6 Calendar commit signature and keep viewport gestures separate from item edits.
- Consult R6-07 for every newly named function; source drift is an Astra checkpoint, never a Luna design choice.
