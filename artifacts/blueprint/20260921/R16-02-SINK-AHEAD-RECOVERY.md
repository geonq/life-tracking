# R16 sink-ahead recovery and durable frame proof

> HISTORICAL: R17-08 section-level authority supersedes conflicting clauses and readiness claims. Read R17-MANIFEST before dispatch.

Planning-only. R16 is the current authority for the crash between sink sync
and receipt update. It refines R15-02 without adding a sink database or sidecar.

## Durable archive frame and discovery

Every partial/final archive frame is one bounded record in the existing sink:
`magic[4]="LOS8" || version UInt8=8 || frameOrdinal UInt64BE ||
frameKind UInt8 || payloadLength UInt32BE || payload bytes || frameHash[32]`.
`payloadLength` is `0...1,048,576`; a record is at most 1,048,626 bytes.
`frameHash = SHA256(Frame("LifeOS/archive-frame/v8", BinaryHeaderWithoutHash
|| payload))`, where `BinaryHeaderWithoutHash` is the exact magic/version/
ordinal/kind/length byte sequence above. The payload remains the canonical R15
archive/carrier bytes; this wrapper is the only durable frame index and is part
of the final artifact hash. No JSON or base64 representation participates in
this hash.

```swift
struct LifeOSSinkTailV8: Sendable {
  let archiveID: UUID; let planHash: String; let byteOffset: UInt64
  let nextFrameOrdinal: UInt64; let lastDurableFrameHash: String?
  let frameCount: UInt64; let completeBoundary: Bool; let finalFooterSeen: Bool
}
protocol LifeOSDurableArchiveSinkV8: Sendable {
  func inspectPartial() throws -> LifeOSSinkTailV8
  func append(_ frame: LifeOSArchiveFrameV8) throws
  func sync() throws
  func truncate(to byteOffset: UInt64) throws
  func finalize() throws -> LifeOSFinalizedArchiveV8
}
```

`append` validates the supplied hash from those binary bytes, writes one full
record, and never reports success before the record bytes are present in the
sink buffer. `sync` calls file `fsync`; `finalize` writes/syncs the final footer,
fsyncs the file and parent directory, then returns `LifeOSFinalizedArchiveV8`.

`inspectPartial` scans from byte zero, verifies magic/version/length, ordinal
continuity, frame-kind plan order and each hash, and stops at the first
incomplete record. It returns `sinkMalformed`, `sinkPlanMismatch` or
`sinkHashMismatch` rather than guessing. It never loads more than one bounded
record. The tail hash is null only when `nextFrameOrdinal=0`.

The referenced frame/result types are fixed in this sheet:

```swift
struct LifeOSArchiveFrameV8: Sendable {
  let archiveID: UUID; let planHash: String; let frameOrdinal: UInt64
  let frameKind: LifeOSEmissionFrameKindV7; let payload: Data; let frameHash: String
}
struct LifeOSFinalizedArchiveV8: Sendable {
  let relativePath: String; let byteCount: UInt64; let artifactFileHash: String
  let archiveHash: String; let manifestRootHash: String
}
enum LifeOSSinkRecoveryResultV8: Sendable {
  case alreadyAligned, adopted(firstOrdinal: UInt64, lastOrdinal: UInt64)
  case truncatedInvalidSuffix, finalArtifactAvailable
}
```

`LifeOSArchiveFrameV8` is accepted only when its fields reproduce the scanned
record bytes; callers cannot supply a different `frameHash`. `inspectPartial`
returns `LifeOSSinkErrorV8`, a closed `Error, Sendable` enum with raw values
`sinkMalformed=1`, `sinkPlanMismatch=2`, `sinkHashMismatch=3`,
`sinkReceiptAhead=4`, `sinkFinalArtifactMismatch=5`, `diskFull=6`,
`operationCancelled=7`, and `archiveIOFailed=8`. The 32-byte wire digest is
represented as lowercase hex only at the Swift model boundary.

## Receipt proof and append order

`LifeOSEmissionCursorV8.durableFrameHash`, `LifeOSReceiptTransitionV8.durableFrameHash`
and the log projection `durableFrameHash` must all equal the sink's
`lastDurableFrameHash`; null is required at ordinal zero. The only successful
per-frame order is:

1. Build the exact planned frame for the recorded next cursor.
2. `sink.append(frame)`, then `sink.sync()`.
3. Re-read the tail and compare ordinal/hash.
4. `receipt.advanceEmission` with expected head, next cursor and that hash.

The receipt update is the only operation after the sink sync. A disk-full or
cancellation error leaves the sink and receipt untouched at their last durable
boundary and returns `sinkWriteFailed` or `operationCancelled`.

## Recovery decision table

`reconcileSinkAhead(_ tail:for:)` is the sole recovery entry point:

```swift
func reconcileSinkAhead(_ tail: LifeOSSinkTailV8,
                        for log: LifeOSReceiptLogV8) throws -> LifeOSSinkRecoveryResultV8
```

* `tail.nextFrameOrdinal == cursor.frameOrdinal` and hashes agree: return
  `alreadyAligned`; no write.
* Tail is ahead: scan every frame from the receipt ordinal. Adopt only when
  each frame is the byte-for-byte frame generated by the stored plan, with
  contiguous ordinals and the expected pass/kind/path/pack/chunk. Call
  `advanceEmission` once per missing frame; each call is a separate atomic
  receipt replacement. Return `adopted(firstOrdinal,lastOrdinal)`. A crash
  during adoption repeats from the first receipt cursor; already adopted
  `(ordinal,hash)` pairs return idempotent no-op.
* Tail is behind the receipt: compare its last hash and offset to the receipt's
  durable proof. If it cannot prove the receipt prefix, return
  `receiptAheadOfSink`; never lower the receipt cursor or invent a frame.
* Tail has an incomplete/unhashed suffix after the receipt boundary: truncate
  only bytes after the last verified boundary, fsync the file and parent, then
  return `truncatedInvalidSuffix`. A valid planned frame ahead is adopted, never
  truncated. A valid but unplanned frame blocks with `sinkPlanMismatch`.
* A complete final footer exists: verify the full plan, footer and raw
  `artifactFileHash`; only then return `finalArtifactAvailable`. A footer with
  any mismatch is blocked and never adopted.

`LifeOSReceiptStoreV8.reconcileSinkAhead` checks the receipt head before every
frame and uses the same expected head on retry. `durableFrameHash` is included
in the transition hash preimage, so a same ordinal with a different frame
hash is `receiptIdentityConflict`. No replay creates duplicate frames because
the scanner compares ordinal/hash before append.

## Bounds, ownership and evidence

The sink permits 1,048,576-byte payloads, 26 data packs, 26 manifest packs,
and the R15 global ordinal bound `<= 2^32-1`; ordinary files are chunked before
the sink. P18 owns `LifeOSDataArchiveWriter.emitFinalized`, sink recovery and
receipt calls in the existing writer/coordinator. P01 owns frame canonical
bytes and hash domains. Required evidence is a crash probe at each step above,
including append-before-sync, sync-before-receipt, adoption interruption,
truncation and final-footer verification; this evidence is external to the
sealed planning contract.
