## 3. Selection, authority and bookmarks
Only the broker's explicit user picker result can initiate production selection: Mac NSOpenPanel chooses one directory; iPhone UIDocumentPickerViewController(forOpeningContentTypes: [.folder], asCopy: false), with cancel/rejection returning no grant. Picker adapter is not installed into app navigation in C.
Never enumerate iCloud/Obsidian roots to find a vault, use a remembered absolute path as authority, or infer that Python Trading is intended. User chooses the vault ROOT, not LifeOS/ or its parent; show/return selected root plus intended LifeOS/ scope before initialize confirmation in later UI wiring.
Reject Uni (case/diacritic-normalized component), aliases/symlinks, regular files, volume roots and nested selection inside a known LifeOS scope. Validate selected URL provenance/ubiquitous metadata; unknown provider identity is unsupported, not guessed. Production supports explicitly selected iCloud Drive/Obsidian directories only; internal test factory accepts owned disposable local roots and cannot be selected via production settings.
Read `.obsidian` directory metadata only as a vault-root signal, never its contents; missing/ambiguous root signal requires explicit root confirmation in broker, not automatic parent walking. The broker retains that confirmation in `PlanningUserSelectedDirectory`, with internal construction restricted to the broker and test factory; select(selection:intent:) consumes it, never a public raw URL. No network URL or deep link can mint it.
Authority is selected directory identity plus marker UUID, constrained to its literal `LifeOS/` child. Read/write nothing else except root metadata and scoped directory entries needed to validate LifeOS spelling. Do not follow links/references into sibling notes, attachments, Uni or `.obsidian`.
Initialize: require explicit `.initialize`; LifeOS must be absent or empty, with no normalized sibling collision. Persist bounded local selection intent first (new vault UUID/generation); create LifeOS via mkdirat, write/flush an exclusive marker temp, publish `.lifeos-vault.json` using exclusive rename, flush directory, then persist grant. Never adopt an unmarked nonempty folder or replace a marker.
Marker is existing `PlanningVaultIdentity` JSON <=4 KiB. Attach requires `.attach(expectedVaultID:)` and matching valid marker; unknown versions/mismatch block without repair. Crash during initialization is resumed only with the saved intent and exact UUID; foreign/partial contents require review, never recursive deletion.
Use existing `PlanningDeviceVaultGrant`: bookmark <=64 KiB, device ID local, generation local, lastValidatedRootIdentity = selected vault root. Journal publication context rootIdentity = pinned LifeOS directory. Persist grants atomically under private app Application Support, never in vault/sync/defaults/logs; protected file on iOS, 0600 file/0700 private directories, backup excluded.
Mac: create/resolve with `.withSecurityScope`; iOS: create normal bookmark options `[]`, resolve with supported noninteractive options and `.withoutImplicitStartAccessing`, then explicitly start scope. `.withSecurityScope` is unavailable on iOS in installed NSURL.h. Always balance every successful start with stop, including throw/cancel paths.
Resolve without UI on restore. Stale bookmark: acquire scope, verify same marker and directory identity, regenerate bookmark, atomically persist before marking ready. Failed refresh -> needsReselection and retain old grant/pending data. Do not accept relocation/identity changes on marker alone; explicit re-selection/attach required.
Selection/attach/revoke increments generation. Bookmarks/inode identities are device-local and MUST NOT be copied Mac->iPhone.

## 4. Containment and coordination
All filesystem I/O runs off MainActor on ONE serial worker; actor prevents overlapping selection/publication and does not allow async reentrancy to invalidate leases unnoticed. Never hold a SQLite transaction/operation lock while waiting on coordination or external I/O.
Acquire NSFileCoordinator access before opening/materializing provider files. Coordinate parent namespace and target together (writing intent for parent, target `.forReplacing`/`.forDeleting` where applicable); keep descriptor operations wholly inside accessor. Use returned URLs only after revalidating authority, not original URL strings. Reads coordinate target plus required parent metadata.
No nested coordinators or await inside the accessor. Async coordination has one active Operation, cancellation token and generation check before every write; timeout cancels coordinator best-effort and reports unavailable. Never free descriptors/scope while accessor still executes or claim a hard OS-I/O timeout; retain the single lane until it exits.
Open selected root with no-follow safeguards; traverse each child with openat(parentFD, oneSegment, O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC), fstat/fstatat(AT_SYMLINK_NOFOLLOW), rejecting device changes, aliases, mount triggers and non-directories. Retain descriptor chain; map S_IFREG/S_IFDIR to journal fileType 1/2 (not raw mode bits).
At the leaf use O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC; accept regular file only, reject hard links (nlink != 1), special files, symlinks and unsupported provider behavior. Check size before allocating, bounded read loop with EINTR/short-read handling, cap+1 detection and before/after fstat + current-name identity validation. Changed read -> retry later, not a snapshot.
Before publication, re-open chain from pinned root and compare each parent dev/inode, recheck root marker and lease generation; after syscall revalidate chain again. All namespace operations use final basenames relative to held parent FD, never concatenate an absolute path and call FileManager replace/remove.
Descriptor authority prevents following a replacement parent into an attacker-selected tree. A renamed-away pinned parent is not silently treated as the current vault path: report identityChanged and retain evidence. Pre/post checks cannot prevent the instantaneous hostile rename race; do not claim lexical-path containment under arbitrary concurrent ancestor relocation.
Enumerate sibling names under held descriptors and compare existing PlanningValidation.normalizedReferencePath semantics before create/open, including Unicode/case/diacritics and LifeOS spelling. Bounds: 4,096 entries per directory, 16,384 visited entries per scan, depth <=64, path <=1,024 bytes. Over-limit -> explicit backpressure; no partial listing reported complete.
Uncreated nested parents may be created only segmentwise after a staged request, within LifeOS and the coordinated lease; re-open/validate each mkdirat result. Never delete parent directories on failure; resumable empty directories are safe. No recursive createDirectory convenience call on vault paths.
Capabilities require exclusive rename, swap rename, descriptor traversal, reliable local identities and directory flush. Unsupported filesystem/provider -> readable if safe, publishing disabled with unsupportedFilesystem; do not fall back to remove+move, truncation, path-only replacement or cross-volume copies.
Windows reparse handling is not implemented in Swift C: no SMB/Windows path/provider publication fallback. Reject provider aliases/indirections here; handle Windows native identity/reparse protections only in its later transport packet.
NSFileVersion unresolved conflicts are surfaced as conflict/blocked; never mark versions resolved/remove versions automatically. Foreground bounded rescan supplies freshness; long-lived file presenters/watchers and their background lifecycle are deferred.

## 5. Raw bytes, references, local persistence and bounds
`read(path:)` returns existing PlanningDocumentSnapshot plus freshness/access wrapper. Exact raw bytes -> SHA256/version -> codec validation; decoding must not rewrite the file. Malformed remote content stays untouched, reported invalidDocument; preserve last known good cache separately.
Canvas file/background references are vault-relative in Obsidian. Preserve all encoded references; only dereference exact `LifeOS/<valid PlanningStoredPath>` after stripping that prefix once. Outside-scope/attachment references remain unresolved/read-only metadata. Later node creation must emit LifeOS-prefixed links; do not reinterpret `Projects/x.md` as `LifeOS/Projects/x.md`.
Stage validates request/vault/path/payload and calls journal.stageMutation before acknowledging durable local save. Publication acknowledgement is separate. Offline stage succeeds only for an already selected identity; unselected cannot queue guesses. Dirty bytes live only in accepted journal.
Cache is private local, <=32 MiB/256 records, atomic content-addressed blobs plus bounded index, LRU clean eviction, generation/vault/path/version validation before load; cap index at 512 KiB before decoding. Cache absence is unavailable, never filesystem absence. Cache write failure must not convert durable mutation success into failure or discard dirty state.
Retain journal limits: Canvas 2 MiB, Markdown 1 MiB, 1,024 pending, 64 MiB retained payload, 256 MiB DB, 64 attempts/mutation, 16,384 history. No new timer-driven full drain. Recovery pass <=32 entries/16 MiB materialized, 2-second admission budget between operations; provider wait time is separate.
Private attempt manifests <=16 KiB each, <=1,024 total; raw backup/witness preservation budget <=64 MiB/256 live artifacts, checked/reserved before mutation. Hit limit -> backpressure without deletion of unresolved evidence. Count orphan owned files too; never trust only in-memory accounting after restart.
Attempt manifest v1 includes vault/device/generation, mutationID/fingerprint, attemptID, operation/path, expected/proposed versions, root/parent chain identities, stage identity, exact reserved basename, backup digest, phase (intent/verified/cleanupPending), verified outcome and safe error code. No bookmark or arbitrary absolute path; validating decode before allocation, unknown schema untouched.
Manifest is a filesystem evidence supplement, not a second conflict/mutation state machine. Store under private `LifeOS/Planning/<vault UUID>/filesystem/`; atomic 0600 replacement+flush, 0700 parent, no-follow same discipline. Journal remains sole authority for logical mutation/decision; contradictory evidence blocks. No Packet B schema migration.

### Complexity and allocation contract
Let B <=2 MiB be document bytes, D <=64 depth, E the total bounded sibling entries examined, N <=16,384 retained mutations and R <=32 recovery entries. Traversal+collision check+hash+publication is O(D+E+B), with expected O(1) hash-set lookup; no sorting the entire vault. Case-fold string work is counted in E as name bytes, not constant-time magic.
Existing Canvas validation is O(V+edges+input bytes); existing canonical encoding sorts object keys, so preserve its O(sum k log k + output bytes) cost, not an invented O(n) guarantee. No codec rewrite or per-frame filesystem work in C.
Adapter recovery performs O(R) operations plus their bounded I/O. Packet B currently uses remaining-row COUNT and validation scans: its worst case includes O(N); do not advertise pure O(log N+R) without changing/reviewing the journal. Cache metadata LRU work is bounded O(256), manifest sweep O(1,024).
Memory: one recovery page <=16 MiB plus at most three bounded document buffers (<=6 MiB), <=64 KiB I/O chunk, <=512 KiB cache index, one <=16 KiB manifest and bounded directory-name/identity metadata; decode one document at a time. Codec object allocation adds O(B+V+edges) with existing node/depth caps. Disk cache is NOT loaded wholesale; do not accumulate results across pages. Report measured peak increment separately from these logical buffer bounds.
Descriptors: <=D+8 per active operation, one scoped lease/coordinator/worker, no leaked FD on any failure. Local disk ceiling is journal limits plus 32 MiB clean cache, 64 MiB preservation budget and <=16 MiB manifest metadata; same-directory stages/displaced files count toward the preservation cap. Reserve capacity with checked arithmetic; free-space preflight is advisory and ENOSPC remains tested.

## 6. Publication protocol (one document; no multi-file transaction claim)
P0: obtain durable request, validated lease/capabilities and raw observation under coordination. If observed raw version differs from expected, persist PlanningConflict with actual bounded observed bytes and local request bytes; do not start a context with mismatched version. Identity change also conflicts even if bytes equal when reconciling an existing attempt.
P1: allocate attempt UUID; persist local intent with parent identities and reserved `.lifeos-stage-UUID`; call beginPublication(context:) with expected observation. Private backup of expected bytes for replace/delete is flushed before P3; its bytes/version and cap reservation are in manifest. If any persistence fails here, no target change.
P2 create/replace: create same-parent witness O_CREAT|O_EXCL|O_NOFOLLOW, mode 0600; handle short writes; flush, re-read bounded bytes and identity, then journal.recordStagedIdentity. Collision with existing witness is never truncated; reconcile only matching manifest/identity or block. Partial witness before stageReady is retained/classified by owned attempt, not guessed by filename.
P2 delete: no staged identity (Packet B forbids it); verify witness destination absent and preserve original private backup. Journal will use the same expected witness basename as a tombstone.
P3: recheck expected bytes, identity, chain and generation; journal.markPublishing must commit BEFORE the destructive syscall. Once publishing, any uncertain return/error remains publishing until reconciled; do not call `.failed` or start a fresh attempt blindly.
P4 create: renameatx_np(parentFD,witness,parentFD,target,RENAME_EXCL); EEXIST is a conflict, never overwrite. Success moves staged inode to target atomically.
P4 replace: renameatx_np(parentFD,witness,parentFD,target,RENAME_SWAP). New inode becomes target and the displaced original becomes witness in ONE namespace operation. Never unlink target first; flags SWAP and EXCL are mutually exclusive. Missing target is conflict, not implicit create.
P4 delete: renameatx_np(parentFD,target,parentFD,witness,RENAME_EXCL), retaining original as same-directory tombstone. Logical deletion is atomic target removal; physical reclamation is separate. Never unlink the target directly.
P5: flush affected data and parent directory; use fsync and supported F_FULLFSYNC for claimed local durability, record unsupported/error semantics rather than ignoring them. Verify target/witness identities and raw versions, plus chain/generation. Create needs staged inode+proposed bytes at target; replace also needs displaced inode+expected bytes at witness; delete needs observed inode+expected bytes at witness and absent target.
P6: persist verified outcome evidence locally, then journal.recordPublicationOutcome(.published(proposedVersion/.absent)). Only now report local publication success; never claim iCloud upload/device receipt. Subsequent external edit does not undo this historical receipt; invalidate clean cache on next read.
P7: cleanup may remove an owned witness only after exact identity/version check, durable success/conflict preservation and successful local backup. Retain private displaced bytes within budget until explicit bounded reclamation policy; C does not prune unresolved evidence or archive journal history. Unknown witness, foreign type or changed bytes is quarantined/reported, never deleted.
Detected post-swap race: preserve displaced witness AND current target observation separately, keep local bytes in journal; persist bounded conflict with actual observed version. Never automatic swap-back/rollback over another edit. Surface that publication encountered interference, with both variants retained; `.published` is forbidden. If bounded conflict cannot represent oversized/invalid evidence, retain witness+manifest and block for inspection without inventing absent bytes.

## 7. Recovery, errors and compatibility
Restore lease first; recovery without valid selected authority only reports pending local work. No attempt crosses generation/root identity automatically. LegacyUnverified attempts are inspection-only; no new manifest fabricated to authorize them.
Read journal.loadPublicationRecoveryPage(after:) and resume same attempt, plus a bounded manifest sweep for published cleanup (journal recovery omits published rows). Freeze cursor maximum sequence, advance over blocked work, return continuation to caller; no recursion or draining loop. Respect retryAfter; preserve original attempt IDs and witness identities.
Prepared/no witness: re-observe and stage safely. Prepared/partial owned witness: verify ownership; recreate only after proving it never reached stageReady/publishing and retaining anomalous contents. stageReady: validate exact stage and unchanged target before continuing same attempt.
Publishing CREATE: exact staged inode/proposed bytes at target and no witness -> verify+finalize; stage still at witness with absent target -> resume exclusive rename; other arrangements -> conflict/inspection.
Publishing REPLACE: target=staged inode/proposed bytes and witness=observed inode/expected bytes -> finalize; target=observed inode/expected bytes and witness=staged inode/proposed bytes -> resume swap; never swap an already-swapped pair back. Any changed/absent/foreign side -> preserve and conflict/inspection.
Publishing DELETE: absent target + witness=observed inode/expected bytes -> finalize; target still exact observed + absent witness -> resume rename; both absent or reappeared/changed target -> ambiguity/conflict, not success inferred from absence alone.
A durable verified manifest can finish the matching historical outcome after journal-write failure even if a later external edit occurred; validate its full lineage and identities/evidence first. Without that evidence, identical hashes alone do not prove an operation happened. Corrupt/missing/contradictory manifest -> block, never rebuild authority from directory names.
Errors distinguish unselected, needsReselection, providerOffline/notDownloaded, permissionDenied, readOnly, diskFull/quota, unsupportedFilesystem, caseCollision, identityChanged, changedDuringRead, malformedDocument, conflict, ambiguousPublication and corruptEvidence. Map errno/NS errors to content-free stable codes; no personal paths/text in logs.
Before publishing: ENOSPC/EDQUOT/EACCES/read-only errors may record retryable/nonretryable failed outcome according to evidence; permission/auth require user action, not periodic retries. After publishing: preserve attempt and reconcile. Disk-full in outcome/manifest/cache cannot remove witness or acknowledge success prematurely.
Eviction/coordination denial/locked device never means absent. Request iCloud materialization only through granted URLs; no blocking main-thread download or eight-day timer. Offline: cached reads explicitly stale, durable edits queued, foreground retry on restored access, raw conflict check on return. Process suspension releases completed leases; in-flight evidence survives termination.
Grant/manifest/cache version 1 are additive local formats; reject unknown major version without rewrite. Existing v1/v2 journals and existing Canvas/Markdown untouched. Another device attaches same marker with its own grant and journal; identities are never synchronized. iCloud duplicate/conflict files are observations, not instructions.
